The System

Iris is a two-part system built around memory, coordination, and community infrastructure. Iris Aelios is a local-first record of my working life. Iris Phylax is the operational layer behind the Hera's Garden Discord community and its connection to The Garden SMP. They share a name and design philosophy, but they run as separate systems with different data, responsibilities, and deployment boundaries.

Iris Aelios: Personal Memory

Aelios runs in the background, notices what I do, and turns that activity into something I can ask questions of later. Instead of reconstructing a week from scattered commits, browser tabs, screenshots, meetings, and half-remembered notes, Aelios creates a searchable record that keeps those pieces connected.

Screen Capture with Change Detection

Periodic captures are compared before storage so near-duplicate frames can be discarded instead of filling the archive with repeated screens.

Vision and OCR Pipeline

Local processing extracts visible text, application context, and a useful description from captured frames while keeping the pipeline ordered and retriable.

Audio and Transcription

System audio and microphone recordings can be transcribed locally with whisper.cpp so meetings and conversations can become part of the same searchable record.

Hybrid Search

SQLite full-text search and sqlite-vec semantic search combine exact matches with conceptual retrieval.

Local Chat with Memory

A conversational interface retrieves relevant history before answering so responses stay grounded in recorded context rather than general model memory.

Calendar Layer

Google Calendar integration coordinates schedules and supports daily and weekly briefings without turning the memory system into a cloud-first application.

Iris Phylax: Community Guardian

Phylax handles the operational work behind Hera's Garden: member verification, moderation, participation systems, support workflows, private member communication, GitHub issue intake, and the bridge between Discord and The Garden SMP. The goal is not to automate the community itself. It is to remove repetitive infrastructure work so the community can run more consistently.

Member Verification

New members move through a button-driven verification flow before receiving access, while returning members can be recognized and restored.

XP and Ranking

Members earn XP from eligible Discord messages, active voice participation, and linked Garden SMP playtime, with cooldowns and activity checks designed to reward sustained participation rather than spam.

Private Iris Channels

One reusable private channel per member gives Iris a server-side place for personal notices, support, and rank-up messages without posting them publicly.

Garden SMP Bridge

Discord and Minecraft communicate through durable MariaDB integration events and commands, supporting account linking, XP, moderation, server notices, reports, and other cross-platform workflows.

Auto-Moderation

Spam and rule violations can be detected and escalated across the community while keeping punishment history available to staff.

GitHub Issue Intake

Structured Discord bug reports can be turned into GitHub issues and routed into the Hera's Garden project workflow without requiring reporters to leave Discord.

Design Principles

Both halves of Iris are built around explicit boundaries and durable state. High-frequency Discord behavior keeps hot-path work small, longer-running tasks are scheduled deliberately, and Minecraft integration uses stored events instead of assuming two services will always be online at the same time. Local inference is preferred where personal data is involved, retriable work is kept retriable, and failures are designed to degrade a feature rather than silently lose the underlying information.
